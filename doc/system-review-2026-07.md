   (履歴から削除しても漏洩済みとみなすのが安全)

## 🚀 速度改善

### 1. 全操作が「全データ再取得」になっている(効果: 大)

ブロックの移動・リサイズ・削除のたびに `revalidatePath("/")` + `router.refresh()` が走り、
`app/page.tsx:43` の **6 クエリ + Google Calendar API を毎回全部再実行**している。
オプティミスティック更新のおかげで体感は保てているが、サーバー負荷と反映遅延の原因。

**改善案:**

- `fetchCalendarEvents` の結果を `unstable_cache` 等で短時間(1〜5 分)キャッシュする。
  カレンダーはドラッグ操作で変わらないのに毎回外部 API を叩いているのが最大の無駄。
- さらに進めるなら、todos 系の変更は Server Action の戻り値で確定データを返し、
  `router.refresh()` 自体を減らす。

### 2. Google Calendar 取得が初期表示をブロック(効果: 大)

`app/page.tsx:89` で `Promise.all` に含めているため、Google API の応答(数百 ms〜)が
**毎回ページ表示時間に直接乗る**。トグル OFF 時は表示すらしないデータ。

**改善案:** Suspense でストリーミングするか、トグル ON 時にクライアントから遅延取得する。

### 3. `tasks` クエリが無制限(効果: 中、将来効く)

`app/page.tsx:74-78` は全タスクをステータス・件数の制限なしで取得している。
完了タスクが溜まると毎回の転送量が増え続ける。

**改善案:** `status != 'done'`(「完了も表示」ON 時のみ全件)や `.limit()` を追加。

### 4. Droppable スロットが 96 個(効果: 中)

`components/timeline/Timeline.tsx:254` で 10 分刻みのスロットを 96 個の `Droppable` として描画。
ブロック移動は既に自前のポインター計算で実装済みなので、バックログからの DnD も
「タイムライン全体を 1 つの Droppable にし、ドロップ Y 座標からスロットを計算」に変えると
DOM 数とドラッグ時の計算量を大幅に削減できる。

## 🎨 UI 改善

### 1. 現在時刻ライン + 自動スクロールがない(効果: 大)

日次タイムラインなのに「今どこか」を示す線がない。
現在時刻の赤ライン(1 分毎更新)と、初期表示時に現在時刻へ自動スクロールする機能は
この種のツールで最も費用対効果の高い改善。

### 2. ヘッダーのボタン過密

「明日を準備 / GCal / セッション追加 / メール / プロジェクト管理 / ログアウト」が横並びで、
モバイルでは折返して 2〜3 行になる。
メールアドレス・ログアウト・プロジェクト管理はアバターメニュー(ドロップダウン)に集約する。

### 3. `window.confirm` がテーマと不整合

削除確認(`Timeline.tsx:520,583`)がネイティブダイアログで、デザイントークン(paper/ink 系)と落差がある。
アプリ内モーダルか、**「削除 → トーストで元に戻す(Undo)」** に置き換えると確認ステップ自体を消せる。

### 4. ドロップ前の重なり検知がサーバー往復後

重なりがあるとドロップ → サーバー → エラートーストで巻き戻る。
`lib/overlap` の判定ロジックは既にクライアントにあるので、
ドラッグ中に赤くハイライトして事前に伝えるとストレスが減る。

### 5. アクセシビリティ

- ブロック移動・リサイズが**ポインター操作のみ**。
  キーボード代替(選択 + 矢印キーで 10 分移動、Shift + 矢印でリサイズ等)がない。
- リサイズハンドルの `role="separator"` に `aria-valuenow` 等がなく、
  `▶` ボタンは `title` のみで `aria-label` がない。

### 6. GCal トグル状態が毎回リセット

バックログ開閉やソート順は localStorage 永続化済みなのに、
`GoogleCalendarToggle` はページ更新で OFF に戻る。同じパターンで永続化する。

## 🧩 機能改善

1. **振り返り(統計)ビュー** — 計画 vs 実績のデータが揃っているのに日次 CSV しか出口がない。
   週次サマリー(プロジェクト別実績時間、計画達成率)はこのツールの価値を最も引き出す機能。
2. **繰り返しタスク** — 毎日 / 毎週のルーチンを「明日を準備」に自動投入できると日次運用が楽になる。
3. **Google Calendar 連携の深化** — 現状 provider_token が切れると黙って空になる
   (`app/actions/google-calendar.ts:53` は 401 でもログのみ)。
   トークン失効時に「再連携してください」を UI に表示。将来的には計画ブロックのカレンダーへの書き戻し。
4. **タイムライン表示範囲(06:00–22:00)の固定** — 範囲外のセッションは `Math.max(0,...)` で
   06:00 位置に貼り付く(`lib/time.ts:62`)。早朝・深夜勤務があるとデータが壊れて見えるため、
   範囲外データがある日は自動拡張するか設定化する。
5. **キーボードショートカット** — `n`=タスク追加、`t`=今日へ、`←/→`=日移動あたりから。
6. **カレンダーイベントの日跨ぎバグの芽** — `google-calendar.ts:72` の `% (24*60)` は
   深夜 0 時を跨ぐイベントで位置がずれる。現状の表示範囲では実害が出にくいが、範囲拡張時に顕在化する。
