# プロジェクト概要: 個人の運用に最適化したタスク＆Todo管理Webアプリ

> **詳細仕様:** 壁打ちで確定した内容は [product-spec.md](./product-spec.md) にまとめています。実装・設計の判断はこちらを優先してください。

## 1. 開発の背景と目的

既存のタスク管理ツール（Notion, Todoist, TickTickなど）では、「抱えているタスクの全体像（バックログ）」と「今日1日の時間割（タイムライン）」が綺麗に連動せず、日々の運用にマッチしない。

本プロジェクトは、開発者自身のドッグフーディング（自己利用）を最大目的とし、将来的なSaaS（月額課金/フリーミアム）による収益化までを見据えた、独自のWebアプリケーションを構築する。

**GTDの考え方:** Todoカレンダーをホームとし、今日やることが一目でわかる状態を理想とする。カレンダーは夕方の振り返りでだんだん埋まっていく運用を想定する。

## 2. コアコンセプト・定義

```
（任意）プロジェクト → タスク（リーフ） → Todo（日付・時間） → 作業時間計測（分）
```

| 概念 | 説明 |
|------|------|
| **プロジェクト** | 作業の箱（1段のみ）。Inbox・問合せ用を含む。タスクの `project_id` はNULL可 |
| **タスク** | バックログ。親タスク（コンテナ）はTodoに載せない。**リーフのみ**実行・計測対象 |
| **Todo** | その日のコミット。タイムライン上の予定。計測はTodo必須 |
| **未配置Todo** | その日にやるが時刻未定。手動でタイムラインへ配置するまで計測開始不可 |

## 3. 主要機能要件

### ① プロジェクト・タスク（バックログ層）

- プロジェクトの登録・編集（**サブプロジェクトなし**）。システムプロジェクト: **Inbox**, **問合せ・差し込み**
- タスクの登録・編集・削除・ステータス管理。親子タスク（**サブタスク**）対応
- 属性: タイトル、詳細、期限、**見積（分）**、**実績（分・セッション集計）**
- プロジェクトの**付け替え**（Inbox ↔ 案件 ↔ なし）
- 期間内・未実施などの**警告**（カレンダーへの自動配置はしない）

### ② Todo管理（タイムライン層）

- **タイムボックスUI:** 15分目盛り、Todoは**可変長**（10分〜）。デフォルト30分
- リーフタスクをDnDで配置。親タスクは配置不可
- **割込計測:** タイムラインからラベル付き実績を即記録（個別タスクは増やさない）
- **未配置Todo:** 今日のコミットのうち時刻未定のもの

### ③ 作業時間計測

- **開始/停止**を基本（同時に1セッションのみ）
- **手動修正・手動追加**（開始・終了時刻必須）で停止忘れ・計測忘れに対応
- 実績は紐づく**リーフタスク**に蓄積
- **ポモドーロタイマー**は長時間作業向けの任意機能（計測は分単位）

### ④ 明日を準備（繰越・定期）

- 夕方の**単一操作**で翌日を準備
- **配置優先順位:** ①時刻あり定期 → ②時刻なし定期（30分仮配置）→ ③今日の残り（30分仮配置）
- 実行後はユーザーが手動で時刻・長さを調整
- 定期（第一弾）: **毎日 / 平日 / 毎週○曜**
- 実績は繰越後もタスクに維持。タスクは未完了のまま

## 4. 将来的な収益化

- **フリーミアム:** 基本機能無料。タスク数上限解除、外部カレンダー連携、**見積と実績（時間）の分析**などを有料（Stripe）

## 5. 技術スタック（確定）

- **ホスティング:** Vercel
- **フロントエンド:** Next.js (App Router) / React / Tailwind CSS
- **DB・認証:** Supabase（Postgres + Auth）
  - ログイン: **Google OAuth** + **メール**（登録・ログイン）
  - データ隔離: 全テーブル `user_id` + **RLS**
- **DnD:** `@hello-pangea/dnd` など

詳細は [product-spec.md §11](./product-spec.md#11-技術スタック確定) を参照。
